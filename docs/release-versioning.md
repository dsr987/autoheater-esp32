# Версионирование Autoheater ESP32

Каноническая версия хранится в `firmware/app/app.cpp` в маркере `CHANGELOG_VERSION`, формат — `MAJOR.MINOR.PATCH`.

Каждый PR в `main` обязан иметь ровно одну метку выпуска и раздел `## Changelog` с хотя бы одним пунктом. Метки:

- `release:patch` — исправления; 0.1.0 → 0.1.1.
- `release:minor` — совместимая новая функция; 0.1.0 → 0.2.0.
- `release:stable` — первый стабильный релиз; 0.x.y → 1.0.0.
- `release:major` — несовместимое изменение после 1.0.0.
- `release:none` — документация, исследование и CI без выпуска новой прошивки.

После успешной сборки слитого PR автоматизация находит PR по SHA коммита, проверяет метку и changelog, обновляет версию и changelog в `app.cpp`, записывает номер обработанного PR в `.github/release-automation/state.json` и создаёт отдельный PR с меткой `release:none` для метаданных. Идемпотентность не позволяет повторно повысить версию за один PR.

Публикация GitHub Release происходит только при изменении версии относительно родительского коммита. Для PR `release:none` версия не меняется и новый релиз не создаётся.

## Секрет для автоматического PR

Добавьте `RELEASE_AUTOMATION_TOKEN` в Settings → Secrets and variables → Actions. Это fine-grained PAT для данного репозитория с правами Contents: Read and write и Pull requests: Read and write. Он нужен для отправки ветки автоматизации и слияния PR; не сохраняйте токен в репозитории.

Сборка прошивки не подтверждает электрическую совместимость или протокол отопителя.
