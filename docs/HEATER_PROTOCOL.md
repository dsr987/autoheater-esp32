# Реверс протокола китайской дизельной автономки (шина пульт↔блок)

## Физический уровень (подтверждено)
- Полудуплексный UART по одному проводу, **9600 бод, 8N1**, логика 5 В.
- Проводка: красный +5 В (питание), синий — данные, чёрный — GND.
- Мастер — пульт, слейв — блок печки. Цикл опроса ~1,13 с.

## Формат кадра (подтверждено на >15000 кадров)
```
[SYNC][CMD][LEN_HI][LEN_LO][DATA × LEN][CRC8]
```
- SYNC: `0xA5` пульт, `0xA0` блок печки
- LEN: 16 бит big-endian, длина DATA
- CRC8: **CRC-8/MAXIM** (полином 0x31, LSB-first 0x8C, init 0x00, без xorout),
  считается по всем байтам от SYNC до конца DATA включительно.
  Совпадение на 98,8–100 % кадров всех логов; одиночные битовые сбои ловятся.

## Команды
| CMD | Направление | Формат DATA | Смысл |
|-----|-------------|-------------|-------|
| 0x30 | пульт → печка | [reg] | чтение регистра |
| 0x00 | печка → пульт | [байты значения] (1/2/4) | ответ на чтение |
| 0x01 | пульт → печка | [reg][float32 LE] или [reg][uint8] | запись параметра |
| 0x20 | пульт → печка | [idx][float32 LE] | телеметрия пульта (idx0 = t° датчика пульта) |

Внутри кадра пауза между байтами ровно 10 битовых интервалов (1,04 мс).
Записи/команды пульта шлются **троекратно** с интервалом ~21 мс.

## Цикл опроса
1. `0x01` запись текущей мощности в reg 0x01 (каждый цикл!)
2. Две телеметрии `0x20` (idx0 = t° датчика пульта, idx1 = 0.0 всегда)
3. 8 чтений подряд: `0x0B, 0x0C, 0x50, 0x20, 0x23, 0x24, 0x16, 0x10` — на каждое ответ ~14 мс

При старте пульта (подача питания): опрос настроек — 0x01, 0x05, 0x0B, 0x01, 0x03, 0x04, 0x0C, 0x10, 0x66.

## Регистры
| Рег | Смысл | Уверенность |
|-----|-------|-------------|
| 0x01 (запись) | текущая уставка мощности, Вт (1000/1900/2800/3700/4600); пульт переписывает каждый цикл | высокая |
| 0x03 | 1 = старт, 0 = стоп; при чтении — последняя сохранённая мощность | высокая |
| 0x50 | машина состояний (см. ниже) | высокая |
| 0x0C | номер шага программы (1–13) | высокая |
| 0x24 | напряжение питания, В (float) | высокая |
| 0x20 | температура узла печки, °C (float) | высокая |
| 0x16 | обороты вентилятора (u32) | высокая |
| 0x10 | счётчик доз топлива (u32, персистентный) | средняя-высокая |
| 0x0B | код ошибки (0xFF = норма) | средняя |
| 0x02 (запись 0), 0x04, 0x05, 0x23, 0x66 | неизвестно | низкая |

## Машина состояний (0x50) — пуск на мощности 5, полный таймлайн
| t от старта | 0x50 | шаг 0x0C | Что происходит |
|-------------|------|----------|----------------|
| +0,3 с | 0x20 | 2 | предстарт, иконка свечи |
| +3,6 с | 0x24 | 5 | розжиг: включается насос (щелчки), вентилятор 0→1500 за 4 с |
| +8,1 с | 0x25 | 6 | прогрев камеры, индикация контроля пламени; пробные впрыски ~0,8/с |
| +98 с | 0x27 | 7–8 | разгон; насос учащается (~2,2/с) |
| +128 с | **0x2F** | 9–11 | выход на режим: вентилятор 1500→4400 (~3 мин), свеча ещё работает (U падает до 13,0 В) |
| +261 с | 0x2E | 11→13 | рабочий режим: свеча потухла (U 13,4–13,5), t° узла растёт к 210+ °C |
| (+321 с) | 0x2E | 13 | установившееся горение |

Шаги: 1 (предпроверка) → 2 (свеча) → 5,6 → 7,8 → 9,10,11 → 13 (шаг 12 не наблюдался).

## Калибровка по мощности (установившийся режим)
| Мощность | Вентилятор 0x16 | Дозы 0x10 | Температура узла 0x20 |
|----------|-----------------|-----------|----------------------|
| 1000 Вт | 2400 | ~1,7–2,3/с | 167–250 °C (зависит от истории) |
| 1900 Вт | ~2900 | ~3,1/с | — |
| 2800 Вт | ~3300–3800 | ~3,7/с | — |
| 3700 Вт | ~3869+ | ~4,35/с | — |
| 4600 Вт | 4400 | ~4,5/с | 210–253 °C (пик) |

- Вентилятор и частота дозирования имеют **большую постоянную времени** (~30–60 с и больше):
  на коротких логах значения не успевают выйти на установившийся режим.
- Температура узла: инерция минутная, пик 253 °C на мощности 5.

## Поведение при выключении
Пульт: 3× запись `0x03 = 0`, затем **один** последний опрос `0x0B` — и молчит.
Фаза продувки/выбега на шине **не видна** (мастер перестаёт опрашивать).
Чтобы снять продувку — нужен активный мастер (ESP32), опрашивающий регистры после стопа.

## Прочие наблюдения
- Счётчик 0x10 заморожен в фазах свечи/розжига, тикает только в фазах горения
  (начиная с шага 7 / состояния 0x27) — вероятно, считает только рабочие дозы, не продувочные.
- Значения 0x10 между сессиями не монотонны (23598, 31657, 1883...) — не пожизненный счётчик,
  а счётчик сессии или сбрасываемый.
- Битые кадры (0,2–1,2 %) рассеяны по времени — похоже на ЭМИ от щелчков насоса.
- Скорость 9600 подтверждена трижды: длительность бита 104 мкс, межбайтовая пауза 1,04 мс,
  сходящийся CRC и осмысленные float-значения.
