# Дополнительные предложения по улучшению

Документ содержит предложения, которые не входят в согласованный набор исправлений текущей задачи. Они **не внесены в прошивку** и не должны считаться обязательными изменениями.

## 1. Уточнить семантику счётчика валидных кадров

Сейчас `validFrames` увеличивается для CRC-корректных кадров штатного пульта и для принятых ответов отопителя. Ответы с корректным CRC, но не прошедшие проверку ожидаемого регистра или длины, в счётчик не попадают.

Предложение: в будущем разделить статистику на:
- кадры с корректным CRC;
- кадры с ошибкой CRC;
- корректные по CRC, но неожиданные/неподходящие ответы.

Так будет проще диагностировать физическую шину, не смешивая ошибки передачи с логикой сопоставления ответов.

## 2. Защитить сопоставление ответов с запросами

Сейчас ожидающий ответ описывается одним `pendingRegister` и общим тайм-аутом. Если ответ задержится, а на шине появится следующий запрос, теоретически возможна неоднозначность: поздний ответ может быть сопоставлен не с тем запросом.

Предложение: при дальнейшей доработке рассмотреть очередь ожидаемых запросов либо дополнительную проверку временного окна и активности шины. Сначала стоит подтвердить проблему логами: при наблюдавшейся задержке около 14 мс это не выглядит срочным дефектом.

## 3. Сделать диагностику подавления эха наблюдаемой

Механизм `consumeEcho()` удаляет совпадающие с последней передачей байты. При необычном поведении UART полезно иметь отдельные счётчики:
- полностью подавленных эхо-кадров;
- частичных совпадений;
- истёкших окон эха.

Это позволит проверить работу механизма на реальной шине. Изменять алгоритм подавления эха без аппаратных логов не предлагается.

## 4. Проверить размер разделов flash перед настройкой OTA

До выбора собственной таблицы разделов нужно подтвердить:
- фактический объём flash конкретной платы;
- размер собранного бинарного файла;
- текущую таблицу разделов, используемую средой сборки;
- требование ElegantOTA к наличию двух OTA-слотов.

Только после этого выбирать размеры app0/app1. Таблица разделов из предварительного обсуждения не добавлялась: в корне репозитория не обнаружен `platformio.ini`, поэтому сначала нужно установить фактическую систему сборки и место её настройки.

## 5. Провести аппаратную проверку до дальнейшей оптимизации

При первом подключении к отопителю рекомендуется отдельно проверить:
1. отвечает ли выключенный отопитель на тихий опрос;
2. принимается ли команда старта при отсутствии свежей телеметрии;
3. возвращается ли регистр мощности `0x01` и соответствует ли float32 фактической уставке;
4. не теряются ли кадры при обновлении OLED;
5. корректно ли работает OTA с фактической таблицей разделов.

До получения этих результатов не рекомендуется менять тайминги опроса, формат кадров, CRC или последовательности команд.

## Статус

Все пункты выше — предложения для последующих отдельных задач. В текущем изменении они не реализованы.
