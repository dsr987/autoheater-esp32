# Autoheater ESP32

Исследовательский проект по изучению протокола пульта китайского автономного отопителя и разработке вспомогательного интерфейса на ESP32.

> **Текущий этап:** протокол, распиновка и электрические уровни пока не считаются подтверждёнными, если это отдельно не отмечено в документации.

## Прошивка и OTA

- [Основное приложение](firmware/app/app.cpp) — стартовый Hello World-каркас; логика протокола пока отсутствует.
- [Bootstrap с ElegantOTA](firmware/bootstrap/Autoheater_ESP32_Bootstrap/Autoheater_ESP32_Bootstrap.ino) — первоначальная прошивка через USB.
- [Инструкции по прошивке](firmware/README.md) и [процесс выпуска](docs/release-process.md).
- GitHub Actions собирает основное приложение и bootstrap, упаковывает OTA `.bin` и SHA-256, а затем публикует firmware release.

Первичная настройка: прошить bootstrap скриптом `firmware/bootstrap/flash_bootstrap.bat`, подключиться к Wi-Fi `Autoheater` (пароль `12345678`) и открыть `http://192.168.4.1/update`. Учётные данные OTA: `admin` / `admin`. Эти данные предназначены только для стенда.

## Цели проекта

- Изучить обмен данными между штатным пультом и отопителем, не теряя штатное управление.
- Собрать открытые схемы, описания протоколов и исследования похожих устройств.
- Зафиксировать наблюдения, гипотезы, распиновку и результаты измерений.
- После проверки электрических характеристик начать с пассивного приёма и журналирования.
- Не передавать неизвестные команды на работающий отопитель.

## Безопасность исследования

- Сначала измерить напряжение, полярность и тип интерфейса; GPIO ESP32 не является 5-вольт-толерантным.
- Не считать сходство с другим отопителем доказательством совместимости протокола.
- Не публиковать Wi-Fi-пароли, токены и персональные данные.
- Сохранять исходные дампы и отделять факт от гипотезы.

## Выпуски

Запустите Actions → **Release label setup** → **Run workflow**, чтобы создать стандартные метки, включая `release:none`. См. [процесс выпуска](docs/release-process.md). Автоматическое повышение версии по меткам PR пока не подключено — текущий каркас уже собирает и публикует бинарник по версии из `firmware/app/app.cpp`.
