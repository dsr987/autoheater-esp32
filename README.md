# Autoheater ESP32

Исследовательский проект по изучению протокола пульта автономного отопителя и разработке вспомогательного интерфейса на ESP32.

> **Текущий этап:** протокол, распиновка и электрические уровни не считаются подтверждёнными, пока это не зафиксировано в документации.

## Прошивка и OTA

- [Основное приложение](firmware/app/app.cpp) — Hello World-каркас; протокол пока не реализован.
- [Bootstrap с ElegantOTA](firmware/bootstrap/Autoheater_ESP32_Bootstrap/Autoheater_ESP32_Bootstrap.ino) — первоначальная запись через USB.
- [Инструкции по прошивке](firmware/README.md).
- [Процесс версионирования и релизов](docs/release-process.md).
- GitHub Actions собирает приложение и bootstrap, упаковывает OTA `.bin` и SHA-256. GitHub Release создаётся только при изменении версии.

Первичная настройка: прошить bootstrap скриптом `firmware/bootstrap/flash_bootstrap.bat`, подключиться к Wi-Fi `Autoheater` (пароль `12345678`) и открыть `http://192.168.4.1/update`. Учётные данные OTA: `admin` / `admin`. Эти данные предназначены только для стенда.

## Выбор версии в Pull Request

Каждый PR должен иметь ровно одну метку:

- `release:patch` — исправление существующего поведения;
- `release:minor` — новая совместимая функция;
- `release:major` — несовместимое изменение после 1.0.0;
- `release:stable` — переход с 0.x на 1.0.0;
- `release:none` — документация, исследование или CI без нового выпуска.

Описание PR должно содержать раздел `## Changelog` с хотя бы одним пунктом. После слияния автоматизация обрабатывает метку и changelog, обновляет версию и создаёт PR метаданных. См. [документацию](docs/release-process.md).

Для автоматического слияния PR метаданных добавьте в Settings → Secrets and variables → Actions секрет `RELEASE_AUTOMATION_TOKEN` с правами Contents: Read and write и Pull requests: Read and write. Без этого секрета безопасно выполнится сборка, но автоматическое применение метаданных остановится с явной ошибкой.

## Цели проекта

- Исследовать обмен данными между штатным пультом и отопителем, не теряя штатное управление.
- Собирать схемы, описания протоколов и исследования похожих устройств.
- Фиксировать наблюдения, гипотезы, распиновку и результаты измерений.
- После проверки электрических характеристик начать с пассивного приёма и журналирования.
- Не передавать неизвестные команды на работающий отопитель.

## Безопасность исследования

- Сначала измерить напряжение, полярность и тип интерфейса: GPIO ESP32 не является 5-вольт-толерантным.
- Не считать сходство с другим отопителем доказательством совместимости протокола.
- Не публиковать токены и персональные данные.
- Сохранять исходные дампы и отделять факт от гипотезы.
