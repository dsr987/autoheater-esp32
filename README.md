# Autoheater ESP32 — исследование автономного отопителя

Исследовательский проект по изучению протокола штатного пульта автономного отопителя и разработке вспомогательного интерфейса на ESP32.

> **Текущий этап:** протокол, распиновка и электрические уровни не считаются подтверждёнными, пока это не зафиксировано в документации.

## Прошивка и обновление по сети

- [Основное приложение](firmware/app/app.cpp) — каркас веб-интерфейса; протокол отопителя пока не реализован.
- [Начальная прошивка с ElegantOTA](firmware/bootstrap/Autoheater_ESP32_Bootstrap/Autoheater_ESP32_Bootstrap.ino) — первоначальная запись через USB.
- [Инструкция по прошивке](firmware/README.md).
- [Порядок версионирования и выпуска](docs/release-process.md).
- GitHub Actions собирает приложение и начальную прошивку, формирует файл обновления OTA `.bin` и контрольную сумму SHA-256. Выпуск GitHub создаётся только при изменении версии.

Первичная настройка: загрузить начальную прошивку скриптом `firmware/bootstrap/flash_bootstrap.bat`, подключиться к Wi-Fi `Autoheater` (пароль `12345678`) и открыть `http://192.168.4.1/update`. Учётные данные для обновления: `admin` / `admin`. Эти данные предназначены только для испытательного стенда.

## Выбор версии при запросе на слияние

Каждый запрос на слияние (PR) должен иметь ровно одну метку:

- `release:patch` — исправление существующего поведения;
- `release:minor` — новая совместимая функция;
- `release:major` — несовместимое изменение после версии 1.0.0;
- `release:stable` — переход с версии 0.x на 1.0.0;
- `release:none` — документация, исследование или настройка сборки без нового выпуска.

Описание запроса должно содержать раздел `## Changelog` хотя бы с одним пунктом. После слияния автоматизация обрабатывает метку и список изменений, обновляет версию и создаёт запрос на слияние с обновлёнными метаданными. Подробнее — в [документации о выпуске](docs/release-process.md).

Для автоматического слияния запросов на обновление метаданных добавьте в Settings → Secrets and variables → Actions секрет `RELEASE_AUTOMATION_TOKEN` с правами Contents: Read and write и Pull requests: Read and write. Без этого секрета сборка выполнится, но автоматическое применение метаданных завершится явной ошибкой.

## Цели проекта

- Исследовать обмен данными между штатным пультом и отопителем, сохранив штатное управление.
- Собрать схемы, описания протоколов и результаты исследований похожих устройств.
- Фиксировать наблюдения, гипотезы, распиновку и результаты измерений.
- После проверки электрических характеристик начать с пассивного приёма и записи данных.
- Не передавать неизвестные команды на работающий отопитель.

## Безопасность исследования

- Сначала измерить напряжение, полярность и тип интерфейса: GPIO ESP32 не допускают прямого подключения сигнала 5 В.
- Не считать сходство с другим отопителем доказательством совместимости протокола.
- Не публиковать токены и персональные данные.
- Сохранять исходные записи и отделять факты от гипотез.
